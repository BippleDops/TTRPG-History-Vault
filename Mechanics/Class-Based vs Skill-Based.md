# Class-Based vs Skill-Based

**First Appeared**: D&D classes (1974), RuneQuest skills (1978)
**Category**: Character System Philosophy

## Overview

Class-Based vs Skill-Based represents fundamental character system divide: **Class-Based** (D&D tradition) assigns characters to archetypes (fighter, wizard, thief) with predetermined abilities advancing through levels, creating balanced distinct roles but limiting customization; **Skill-Based** (RuneQuest, GURPS, CoC) rates individual skills allowing à la carte capability selection, creating customization freedom but risking optimization/imbalance, with debate between approaches representing broader design philosophies about player freedom versus balanced design, demonstrating neither approach objectively superior—each serves different creative agendas and player preferences.

**Class-Based** (D&D, Pathfinder):
- Choose archetype (Fighter, Wizard, Rogue, Cleric)
- Gain class abilities at level milestones
- Distinct mechanical roles
- Balanced within class structure
- Limited customization

**Skill-Based** (RuneQuest, GURPS, CoC):
- No classes, just skills rated individually
- Spend points or advance through use
- Complete customization freedom
- Create any concept
- Balance challenges

**Hybrid**: Some games combine (D&D multiclass, skill feats, Pathfinder skill ranks)

**Debate**: Ongoing—represents design philosophy differences

## Class-Based Systems

### Structure

**Archetypes**: Fighter, Wizard, Rogue, Cleric, etc.

**Level Progression**: Abilities at level thresholds

**Hit Dice**: Class determines HP advancement

**Class Features**: Predetermined abilities

**Multiclassing**: Combining classes (with restrictions)

### Advantages

**Balanced**: Playtested class capabilities

**Distinct Roles**: Clear party positions

**Easy**: Choose class, follow progression

**Thematic**: Archetypes provide identity

**New Player Friendly**: Clear paths

### Disadvantages

**Limited Customization**: Locked into class features

**Archetype Restriction**: Must fit class paradigms

**Multiclass Complexity**: Combining classes complicated

**Pigeonholing**: Class defines you

## Skill-Based Systems

### Structure

**Individual Skills**: Rated separately (Persuasion 45%, Stealth 60%, etc.)

**Point Allocation**: Distribute points as desired

**Advancement**: Improve any skill

**Complete Freedom**: Any combination possible

**No Levels**: Gradual improvement

### Advantages

**Customization**: Create any concept

**Freedom**: Not locked into archetypes

**Realism**: People have varied skills

**Unique**: Every character different

**Concept Realization**: Match vision exactly

### Disadvantages

**Balance Issues**: Optimization possible

**Analysis Paralysis**: Too many options overwhelming

**Complexity**: Tracking numerous skills

**Power Disparity**: System mastery advantages

**New Player Confusion**: Where to start?

## Hybrid Approaches

**D&D 5E**: Classes + skill proficiencies + feats

**Pathfinder**: Classes + skill ranks + customization

**13th Age**: Classes + unique features + backgrounds

**FATE**: Aspects + skills + stunts

**Many Modern**: Combining structure with customization

## Design Philosophy

**Class-Based Philosophy**:
- Balanced roles matter
- Archetypes provide structure
- Ease of play important
- Party dynamics from distinct roles
- New player accessibility

**Skill-Based Philosophy**:
- Player freedom paramount
- Simulation over balance
- Customization enables concept realization
- Complexity acceptable for depth
- Experienced player focus

## Cultural Impact

**Neither Won**: Both approaches thrive

**Hybrid Trend**: Modern games combining

**Design Choice**: Neither objectively better—depends on priorities

**Player Preference**: Split based on values (balance vs. freedom)

## Reception

**Class Advocates**: Value balance, clarity, ease

**Skill Advocates**: Value freedom, customization, realism

**Hybrid Fans**: Want both structure and flexibility

## Legacy

Fundamental ongoing design choice. Hybrid approaches increasingly common. Neither method displaced other—both serve different preferences and creative agendas successfully.

## Notes
