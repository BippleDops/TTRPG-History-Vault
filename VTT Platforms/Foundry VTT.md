# Foundry VTT

**Platform Type**: Virtual Tabletop (VTT) - Self-Hosted Web Application
**Launched**: 2020
**Business Model**: One-time purchase ($50 lifetime license)
**User Base**: 100,000+ licensed users (estimated)
**Developer**: Foundry Gaming LLC (Andrew Clayton)
**Website**: https://foundryvtt.com
**Status**: Active with regular updates
**Impact on Industry**: 4/5

## Overview

Foundry Virtual Tabletop (Foundry VTT) emerged in 2020 as a modern, self-hosted alternative to existing VTT platforms, quickly disrupting the market with its one-time purchase model and exceptional modding capabilities. Created by sole developer Andrew Clayton (known as Atropos), Foundry VTT was designed from the ground up using modern web technologies to provide a powerful, flexible platform that users could customize extensively while maintaining ownership of their data through self-hosting.

Foundry's defining characteristic is its open architecture and developer-friendly design. Unlike subscription-based platforms or closed ecosystems, Foundry provides a comprehensive API that enables community developers to create sophisticated modules and game systems. This openness, combined with the one-time $50 purchase price, created a value proposition that attracted experienced VTT users dissatisfied with Roll20's performance or Fantasy Grounds' ongoing costs.

The platform's rapid rise represents a shift in VTT market dynamics. Within two years of launch, Foundry built a passionate community, extensive module ecosystem, and reputation for technical excellence. Its success demonstrated that users valued software ownership, modding capability, and developer transparency, influencing how other platforms approach their business models and community engagement.

## Features and Functionality

### Core Platform Architecture

**Self-Hosted Web Application**:
- Node.js server application
- Users install on own hardware or cloud
- Web browser clients (any device)
- Full data ownership
- No dependency on third-party servers

**Modern Technology Stack**:
- **Backend**: Node.js, NeDB database
- **Frontend**: HTML5, CSS3, JavaScript
- **Graphics**: WebGL for rendering, PixiJS library
- **Communication**: WebRTC for audio/video
- **Real-time**: WebSocket for synchronization

**Installation Options**:
- Self-hosting on personal computer
- Cloud hosting (AWS, DigitalOcean, etc.)
- Third-party hosting services (The Forge, Foundry Server, etc.)
- Docker containers
- Dedicated hardware setups

### Game Management Features

**Scene (Map) Management**:
- Unlimited scenes per world
- Background images with grid overlay
- Multiple grid types (square, hex, gridless)
- Walls for line of sight and movement
- Dynamic lighting sources

- **Walls**: Vision and movement blocking

**Token System**:
- Drag-and-drop token placement
- Linked or unlinked actor data
- Resource tracking (HP, abilities, etc.)
- Status effects and conditions
- Token vision and light emission
- Elevation and token stacking
- Animations and effects

**Combat Tracker**:

## Technical Architecture

### Self-Hosting Infrastructure

**Server Requirements**:
- Node.js runtime environment
- Minimal hardware (Raspberry Pi capable)
- Port forwarding or hosting service
- SSL certificate for HTTPS
- Storage for assets and worlds

**Hosting Options**:

**Local Hosting**:
- Run on GM's computer
- Free (no hosting costs)
- Full control
- Requires port forwarding or VPN
- Works on Windows, Mac, Linux

**Cloud Hosting**:
- AWS, DigitalOcean, Google Cloud
- Always available
- Better performance for distributed players
- $5-$20/month typically
- Technical setup required

**Managed Hosting**:
- The Forge, Foundry Server, others
- Simplified setup
- Integrated asset management
- Monthly subscription
- Less control but easier

### Performance Characteristics

**Advantages**:
- Desktop/server hardware generally better than browser limits
- Efficient WebGL rendering
- Optimized asset loading
- Better handling of large maps
- Lower latency for hosted games

**Considerations**:
- Host hardware affects performance
- Internet upload speed critical for hosting
- Client browsers need modern GPU
- Large worlds require more resources
- Module conflicts can impact performance

### Data Management

**World Data**:
- JSON files for all game content
- Assets stored in file system
- Database is NeDB (lightweight)
- Full backups possible
- Migration between hosts easy

**Data Ownership**:
- Users own all data
- No vendor lock-in
- Export and backup freely
- Privacy control
- Portability
